# ViLM2CCG

**Vietnamese Language Model to Combinational Circuit Graph**

ViLM2CCG is a multi-stage pipeline that converts Vietnamese natural-language descriptions of combinational logic circuits into:

- **CircuitJSON** – a structured intermediate representation (IR)
- **CCG visualizations** – NetworkX + Matplotlib circuit-graph images (PNG/SVG)
- **Synthesisable Verilog HDL**
- **Functional verification** via Icarus Verilog or a pure-Python simulation fallback
- **Streamlit web dashboard** for interactive use

## Core package (`vilm2ccg/`)

| Module | Description |
|---|---|
| `input_module.py` | Rule-based Vietnamese prompt parser; recognises circuit types via regex and extracts numeric parameters from Arabic digits and Vietnamese number words (`hai`, `ba`, `bốn`, …) |
| `circuit_json.py` | Typed `CircuitNode`/`CircuitEdge` dataclasses + `CircuitJSON` container with JSON round-trip serialisation |
| `llm_interface.py` | LM Studio backend (OpenAI-compatible API); Vietnamese Chain-of-Thought system prompt; rule-based fallback for AND/OR/NOT/NAND/NOR/XOR/XNOR, MUX, adders, decoder, encoder, comparator |
| `seq2seq.py` | `CharTokenizer` (character-level, vocabulary built from corpus) + `CircuitSeq2Seq` (`nn.Transformer`, ≈3.8 M params) |
| `visualizer.py` | Topological layered layout via NetworkX; colour-coded node types, edge net labels, legend; returns PNG/SVG bytes |
| `hdl_generator.py` | Translates CircuitJSON to `assign`-style Verilog; MUX as nested ternary expressions |
| `verification.py` | Auto-generates a self-checking testbench from the truth table; compiles/simulates with Icarus Verilog or pure-Python fallback |

## CircuitJSON canonical schema

All CircuitJSON objects conform to the following schema:

```json
{
  "id": "mux_4to1",
  "input_text": "Tạo mạch MUX 4-1",
  "graph": {
    "nodes": [
      {"id": "in_0",  "type": "input",  "name": "I0"},
      {"id": "mux0",  "type": "mux",    "name": "MUX_4to1"},
      {"id": "out_0", "type": "output", "name": "Y"}
    ],
    "edges": [
      {"source": "in_0",  "target": "mux0",  "from_port": 0, "to_port": 0, "name": "w_d0"},
      {"source": "mux0",  "target": "out_0", "from_port": 0, "to_port": 0, "name": "w_y"}
    ]
  },
  "verilog": "// Auto-generated by ViLM2CCG\nmodule mux_4to1 ...",
  "metadata": {
    "num_inputs": 6,
    "num_outputs": 1,
    "num_gates": 1,
    "circuit_name": "mux_4to1",
    "circuit_type": "mux",
    "description": "4-to-1 Multiplexer"
  }
}
```

Each **node** represents a logic gate or signal; each **edge** represents a wire connection between components.  
The `from_dict()` deserialiser also accepts the legacy flat format (`circuit_name`/`nodes`/`edges` at top level) for backward compatibility.

## LM Studio integration (local LLM)

ViLM2CCG uses [LM Studio](https://lmstudio.ai/) as the default local LLM backend.
LM Studio exposes an OpenAI-compatible API on `http://localhost:1234/v1`.

### Steps

1. Download and install LM Studio from <https://lmstudio.ai/>.
2. Load any instruction-following model (e.g. *Qwen2.5-7B-Instruct*, *Llama-3-8B-Instruct*, …).
3. Start the local server inside LM Studio (**Local Server** tab → **Start Server**).
4. Run the Streamlit dashboard and tick **Sử dụng LM Studio** in the sidebar.

### Environment variables (optional)

| Variable | Default | Description |
|---|---|---|
| `LM_STUDIO_URL` | `http://localhost:1234/v1` | LM Studio server URL |
| `LM_STUDIO_MODEL` | `local-model` | Model identifier shown in LM Studio |

```bash
export LM_STUDIO_URL=http://localhost:1234/v1
export LM_STUDIO_MODEL=qwen2.5-7b-instruct
streamlit run app.py
```

### Programmatic usage

```python
from vilm2ccg.llm_interface import LLMInterface
from vilm2ccg.visualizer import visualize_circuit
from vilm2ccg.hdl_generator import generate_verilog

circuit = LLMInterface(
    base_url="http://localhost:1234/v1",
    model="local-model",
    use_fallback=False,
).generate_circuit("Tạo mạch MUX 4-1")
img_bytes = visualize_circuit(circuit)   # PNG bytes
verilog   = generate_verilog(circuit)    # Verilog string
```

When LM Studio is not running, set `use_fallback=True` (the default) to use the built-in rule-based engine.

## Training dataset (`dataset/`)

228 Vietnamese NL prompt → CircuitJSON pairs covering **14 circuit types** with 6–10 phrasing variations each.  
Splits are stratified by circuit type: **train 182 / val 23 / test 23**.

Each split is exported in two formats:

| File | Format | Use |
|---|---|---|
| `train.jsonl` | Alpaca instruction format | General fine-tuning |
| `train_chat.jsonl` | Chat / messages format | LM Studio fine-tuning, OpenAI API |

### Regenerate dataset

```bash
python dataset/build_dataset.py
```

### Fine-tune with LM Studio

1. Open LM Studio → **Fine-tuning** tab.
2. Upload `dataset/data/train_chat.jsonl` (train) and `val_chat.jsonl` (validation).
3. After training, load the new adapter and enable **Sử dụng LM Studio** in the sidebar.

## Training & inference (local seq2seq model)

A fully local training pipeline — no internet connection or pre-trained weights required.

### Train

```bash
# 1. Regenerate dataset (optional)
python dataset/build_dataset.py

# 2. Train for 1 epoch (~110 s on CPU)
python train.py --epochs 1 --batch 4
# Device : cpu  |  Vocab: 112  |  Params: 3,773,552
# Epoch 1/1  train_loss=2.2101  val_loss=1.5079
# ✓ Saved → models/vilm2ccg-t5/

# 3. Train longer for better JSON output quality
python train.py --epochs 10 --batch 4
```

**Architecture:** character-level `nn.Transformer` encoder-decoder, `d_model=256`, 2+2 layers, FFN=1024 ≈ 3.8 M params.  
Training targets are compact CircuitJSON graph structures (Verilog is re-added at inference time by the HDL generator).

### Inference

```bash
# Single prompt
python inference.py --prompt "Tạo mạch AND 2 đầu vào"

# Interactive demo (built-in examples)
python inference.py

# From stdin
echo "Cổng XOR 2 đầu vào" | python inference.py --stdin

# Show raw model output
python inference.py --prompt "Bộ cộng nửa" --raw
```

Example output:

```
Prompt: Tạo mạch AND 2 đầu vào
  source      : model
  id          : and_2in
  circuit_type: and
  inputs/outputs/gates: 2 / 1 / 1
  nodes       : 4
  edges       : 3
  verilog     : yes (262 chars)
```

> **Note:** After 1 epoch the model is still learning JSON structure; `inference.py` automatically falls back to the rule-based engine when the output is not yet valid JSON, so correct CircuitJSON is always returned.

## Streamlit dashboard

The dashboard provides a five-tab result view:

| Tab | Content |
|---|---|
| Analysis | Parsed intent + raw CircuitJSON |
| Graph | PNG visualisation (download) |
| Verilog | Generated HDL source (download) |
| Truth Table | DataFrame |
| Verification | Simulation output |

The sidebar provides LM Studio connection settings (URL, model name, enable/disable toggle) and one-click example prompts.

## Verification

If [Icarus Verilog](https://github.com/steveicarus/iverilog) is installed:

```bash
sudo apt-get install iverilog   # Ubuntu/Debian
```

The verification module compiles and simulates the generated Verilog. Without iverilog a pure-Python gate simulation is used as a fallback.
